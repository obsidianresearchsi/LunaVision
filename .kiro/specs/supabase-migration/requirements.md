# Requirements Document

## Introduction

This specification defines the migration of the EagleEye facial recognition system from browser localStorage to Supabase as the backend database. The migration will preserve all existing data structures while enabling cloud-based persistence, multi-device access, and proper relational data management. The system manages users, suspects with facial recognition tokens, and audit logs for search operations.

## Glossary

- **EagleEye_System**: The facial recognition application being migrated
- **Supabase**: The PostgreSQL-based backend-as-a-service platform
- **Suspect**: An individual record in the criminal database with facial recognition data
- **FaceToken**: A unique identifier generated by Face++ API for facial recognition
- **AuditLog**: A record of search operations performed by officers
- **User**: An authenticated officer or commander using the system
- **NIN**: National Identity Number - a unique identifier for Nigerian citizens
- **RLS**: Row Level Security - Supabase's security mechanism for data access control

## Requirements

### Requirement 1

**User Story:** As a system administrator, I want to migrate user data to Supabase, so that user accounts persist across sessions and devices.

#### Acceptance Criteria

1. WHEN the EagleEye_System initializes THEN the EagleEye_System SHALL connect to Supabase and retrieve user data from the users table
2. WHEN a new user is created THEN the EagleEye_System SHALL insert the user record into Supabase with id, username, role, and created_at fields
3. WHEN bulk officer creation is requested THEN the EagleEye_System SHALL insert multiple user records into Supabase in a single batch operation
4. WHEN retrieving users THEN the EagleEye_System SHALL return all user records from the Supabase users table

### Requirement 2

**User Story:** As an officer, I want suspect data stored in Supabase, so that all team members can access the same criminal database.

#### Acceptance Criteria

1. WHEN the EagleEye_System queries suspects THEN the EagleEye_System SHALL retrieve suspect records from the Supabase suspects table
2. WHEN a new suspect is enrolled THEN the EagleEye_System SHALL insert the suspect record into Supabase with all required fields including face_token, name, crime, nin, location, image_url, and source_url
3. WHEN a suspect record is updated THEN the EagleEye_System SHALL update the corresponding record in Supabase identified by face_token
4. WHEN a suspect status changes THEN the EagleEye_System SHALL update only the status field in the Supabase suspects table
5. WHEN suspects with coordinates exist THEN the EagleEye_System SHALL store latitude and longitude as numeric fields in Supabase

### Requirement 3

**User Story:** As a chief commander, I want audit logs stored in Supabase, so that I can review search history across all officers.

#### Acceptance Criteria

1. WHEN an officer performs a search THEN the EagleEye_System SHALL insert an audit log record into Supabase with log_id, officer_id, search_image_path, timestamp, result_count, and search_type
2. WHEN retrieving audit logs THEN the EagleEye_System SHALL return records ordered by timestamp descending (newest first)
3. WHEN audit logs reference an officer THEN the EagleEye_System SHALL maintain referential integrity with the users table

### Requirement 4

**User Story:** As a developer, I want a Supabase service layer, so that database operations are centralized and maintainable.

#### Acceptance Criteria

1. WHEN the application starts THEN the EagleEye_System SHALL initialize a Supabase client with project URL and publishable key
2. WHEN any database operation fails THEN the EagleEye_System SHALL handle the error gracefully and provide meaningful error messages
3. WHEN the Supabase service is used THEN the EagleEye_System SHALL expose the same interface as the current DatabaseService class
4. WHEN serializing data for Supabase THEN the EagleEye_System SHALL convert TypeScript interfaces to snake_case column names
5. WHEN deserializing data from Supabase THEN the EagleEye_System SHALL convert snake_case column names to camelCase TypeScript properties

### Requirement 5

**User Story:** As a system administrator, I want proper database schema in Supabase, so that data integrity is maintained.

#### Acceptance Criteria

1. WHEN the database schema is created THEN the EagleEye_System SHALL define a users table with id (primary key), username (unique), role, and created_at columns
2. WHEN the database schema is created THEN the EagleEye_System SHALL define a suspects table with face_token (primary key), name, crime, nin, location, image_url, source_url, is_relative_to_id, coordinates_lat, coordinates_lng, dob, gender, physical_marks, status, and notes columns
3. WHEN the database schema is created THEN the EagleEye_System SHALL define an audit_logs table with log_id (primary key), officer_id (foreign key to users), search_image_path, timestamp, result_count, and search_type columns
4. WHEN seed data is required THEN the EagleEye_System SHALL insert the predefined suspect records into the suspects table

### Requirement 6

**User Story:** As a developer, I want existing components updated to use Supabase, so that the migration is complete and localStorage is no longer used for core data.

#### Acceptance Criteria

1. WHEN the crawler indexes a new face THEN the EagleEye_System SHALL save the suspect to Supabase instead of localStorage
2. WHEN the face engine searches for matches THEN the EagleEye_System SHALL query suspects from Supabase
3. WHEN any page component needs data THEN the EagleEye_System SHALL fetch from Supabase using the new service layer
4. WHEN the migration is complete THEN the EagleEye_System SHALL remove localStorage dependencies for users, suspects, and audit_logs data
